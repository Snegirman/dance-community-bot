# Dance Community Bot

Telegram-бот для танцевальной беседы: каждую неделю публикует расписание занятий
и события, которые владелец заранее прислал и подтвердил. Направления занятий —
Popping, Animation и Waving. Самостоятельный поиск событий в интернете не предусмотрен.

## Текущее состояние

Выполнена только базовая инициализация Python-проекта:

- пакет с локальной точкой входа;
- настройки сборки, окружения и Ruff;
- шаблон будущих переменных окружения;
- требования к первой версии и правила разработки.

Работающего Telegram-бота пока нет. Распознавание, хранение данных и публикации
ещё не реализованы. Запуск каркаса печатает сообщение и завершается без сетевых
запросов, ключей, создания базы и расходов на API.

## Быстрый старт

Используем Python 3.13 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Версия Python задана в [.python-version](.python-version), зависимости и инструменты —
в [pyproject.toml](pyproject.toml). Точные версии зависимостей закреплены
в [uv.lock](uv.lock); этот файл хранится в Git.

Если uv установлен локально в `.tools/uv`, добавь его в PATH текущего терминала:

```bash
export PATH="$PWD/.tools:$PATH"
```

Из корня проекта:

```bash
uv sync
uv run dance-community-bot
```

`uv sync` создаст локальное окружение `.venv` и установит пакет и инструменты
разработки. При отсутствии подходящего Python uv может скачать его; для первой
установки нужен интернет. Системный Python менять не требуется.

Также пакет можно запустить как модуль:

```bash
uv run python -m dance_community_bot
```

Проверки:

```bash
uv run ruff check .
uv run ruff format --check .
```

Для форматирования: `uv run ruff format .`. Автоматические тесты добавим вместе
с первой прикладной логикой; сейчас проверяем установку, запуск и линтер.

Файл [.env.example](.env.example) описывает параметры будущих интеграций.
Каркас пока не читает `.env`, поэтому для его запуска заполнять параметры не нужно.
При подключении бота скопируй шаблон в `.env` и внеси реальные значения локально.
Секреты, база, исходные материалы и резервные копии исключены из Git.

## Стек и структура

Проект пишем только на Python. Для дальнейшей реализации выбраны:

| Назначение | Решение | Состояние |
| --- | --- | --- |
| Окружение и зависимости | Python 3.13, uv | Каркас настроен |
| Сборка и проверка стиля | Hatchling, Ruff | Настроены |
| Telegram | aiogram 3, long polling для первого запуска | Ещё не подключён |
| Анализ текста и изображений | Официальный OpenAI Python SDK | Модель и доступ не проверены |
| Постоянное хранение | SQLite | Ещё не подключено |
| Публикация | Шаблон из базы, без вызова ИИ | Ещё не реализована |
| Развёртывание | Один процесс на VPS с постоянным диском | Хостинг и планировщик не выбраны |

Библиотеки интеграций добавляем по мере реализации. Сейчас у приложения нет
внешних runtime-зависимостей. Node.js, TypeScript и grammY не используются.

```text
.
├── AGENTS.md                 # Правила для разработчиков и ИИ-агентов
├── README.md                 # Запуск, требования и дальнейшие шаги
├── .env.example              # Будущие настройки без секретов
├── .gitignore
├── .python-version
├── pyproject.toml            # Метаданные пакета, сборка и Ruff
├── uv.lock                   # Зафиксированные версии зависимостей
└── src/
    └── dance_community_bot/
        ├── __init__.py
        └── __main__.py       # Локальный запуск каркаса
```

По мере реализации отделяем Telegram-обработчики, распознавание, доступ к данным
и сборку публикаций. OpenAI должен находиться за границей модуля распознавания,
чтобы позднее можно было заменить провайдера. Сейчас реализуем только OpenAI,
без fallback и дополнительных провайдеров.

## Сценарий первой версии

1. Владелец присылает материалы боту в личную переписку.
2. Бот сохраняет исходный материал и автоматически запускает распознавание через
   OpenAI. Программа проверяет структурированные данные перед сохранением карточки.
3. Для каждого события бот показывает отдельный черновик с кнопками
   «Сохранить», «Исправить», «Отклонить» и вопросами по недостающим сведениям.
4. Владелец подтверждает запись или исправляет её обычным текстом, например:
   «Начало в 18:30, остальное верно». Дополнительный материал можно прислать ответом
   на карточку, чтобы связать его с тем же событием.
5. Подтверждённая запись сохраняется. Повторного подтверждения каждую неделю нет.
6. По понедельникам бот выбирает занятия и события текущей недели и публикует
   пост с оригинальными афишами. Доступен предварительный просмотр.

Управление доступно только владельцу; участники группы получают публикации.
Для первой версии ориентируемся на текст, пересланные сообщения, фото афиш
и скриншоты. Этот перечень ещё нужно окончательно подтвердить перед реализацией
приёма материалов. PDF и голосовые отложены. Веб-интерфейс не нужен.

## Данные и правила распознавания

| Сущность | Основные сведения |
| --- | --- |
| Регулярное занятие | День недели, время, направление, место, стоимость |
| Исключение из расписания | Конкретное занятие и дата, отмена, перенос или замена |
| Разовое событие | Название, тип, дата и время, место, тарифы и условия, существенные детали, регистрационная ссылка |

У событий сохраняем оригинальные афиши, исходные материалы и статус подтверждения.
Связь с источником должна сохраняться и при разделении одной афиши на несколько
карточек, и при объединении нескольких сообщений. Регулярное расписание задаётся
один раз и меняется по необходимости. Конкретное расписание ещё не задано.

Правила извлечения:

- Не выдумывать отсутствующие сведения. Неизвестное значение хранить явно.
- Отсутствующая стоимость означает «не указана», а не «бесплатно».
- Сохранять все тарифы вместе с условиями и сроками их действия.
- При неоднозначной дате, отсутствии года или формулировке «в эту субботу»
  запрашивать уточнение, а не подставлять дату молча.
- При противоречиях текста и афиши показывать расхождение владельцу.
- Несколько мероприятий в одном материале предлагать отдельными карточками.
- Публиковать оригинальную афишу, а не сгенерированную замену.

ИИ используется при добавлении и исправлении материалов. Недельный пост
собирается детерминированно из подтверждённых данных без обязательного запроса к модели.

## Надёжность и эксплуатация — требования к реализации

- Проверять Telegram ID владельца и личный чат во всех административных действиях,
  включая callback-кнопки. Username не использовать для авторизации.
- Поддержать предпросмотр, редактирование и отмену событий.
- Хранить очередь необработанных материалов и позволять повторить обработку.
- При недоступности OpenAI сохранять материалы и уведомлять владельца;
  подтверждённое расписание должно продолжать публиковаться.
- Учитывать отправленные публикации и сообщения, предотвращать повторы при
  перезапуске и повторном срабатывании планировщика, учитывать частичную отправку.
- Использовать часовой пояс `Europe/Moscow`; неделя — с понедельника до следующего
  понедельника, правая граница не включается. Время понедельничного поста ещё не выбрано.
- До включения автопубликации явно задать время и целевую группу.
- Хранить SQLite, исходные материалы и афиши на постоянном диске. Предусмотреть
  согласованные резервные копии базы и файлов, а также проверку восстановления.
- Хранить ключи в окружении, не выводить их и содержимое личных материалов в логи.
- Сохранять расход токенов и модель для запросов OpenAI. Денежную оценку делать
  только по проверенным тарифам, отдельно от доступного баланса аккаунта.

## Что нужно определить перед подключением

- Зарегистрировать бота, задать токен, Telegram ID владельца и группы; проверить
  право бота отправлять сообщения и афиши в группу.
- Выбрать модель OpenAI с изображениями и структурированным выводом.
- Проверить доступность OpenAI API для аккаунта и региона, ключ, активацию
  и баланс API-кредитов. Наличие ChatGPT Pro само по себе не подтверждает готовность
  API. [Инструкция по API-кредитам ChatGPT](https://developers.openai.com/api/docs/guides/chatgpt-api-credits).
- Задать расписание занятий, подтвердить форматы материалов и выбрать время поста.
- Выбрать VPS и место хранения резервных копий.

Доступ и баланс API в рамках инициализации не проверялись. Fallback, покупка
резервных кредитов и автопополнение не согласованы и не входят в текущую работу.
