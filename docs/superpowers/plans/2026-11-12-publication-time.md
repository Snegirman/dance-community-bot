# Время автопубликации в интерфейсе бота

> Исполнение: superpowers:subagent-driven-development; код и тесты — luna_worker,
> ревью и исправления — главный агент. Существующие изменения сохраняем, без коммитов.

**Цель:** менять время через `/settings`, сохранять в SQLite и применять без перезапуска.
**Архитектура:** одна настройка с ревизией, привязанные к ревизии сообщения ввода,
планировщик читает сохранённое время; ENV задаёт только начальное значение новой базы.
**Стек:** Python 3.13, uv, aiogram, SQLite, pytest, Ruff; новых зависимостей нет.
**Спецификация:** [сценарий и границы](../specs/2026-11-12-publication-time-design.md).

## Проверка рисков

- Отключение не должно отменяться после перезапуска из-за ENV.
- Старый callback/ответ и повтор доставки не должны возвращать старое время.
- Настройки не перехватывают ответы на карточки событий; чужие пользователи и группы не имеют доступа.
- Изменение времени не отправляет пост немедленно и не повторяет начатый выпуск.
- Уведомление о прежнем пропуске не блокирует новый будущий срок в ту же неделю.

## Task 1: Настройка, интерфейс и применение в планировщике

**Файлы:** новые `storage/settings.py`, `settings_handlers.py`,
`tests/test_publication_settings.py`; связанные изменения `schema.sql`, `models.py`,
`storage/__init__.py`, `storage/base.py`, `storage/automation.py`, `scheduler.py`,
`bot.py`, конфигурации и её тестов, README и `.env.example`.

**Интерфейсы:** типизированная настройка содержит `time | None` и ревизию;
Store читает/однократно инициализирует её и атомарно меняет по ожидаемой ревизии.
Сохранённая привязка запроса содержит chat/message ID и ревизию. При том же
значении новая ревизия не нужна. Уведомления планировщика учитывают ревизию
настройки; существующий журнал выпусков остаётся общим с ручной отправкой.

## Результат 12.11.2026

Реализовано через `/settings`, ForceReply и SQLite; схема версии 7, без миграций
и новых зависимостей. Главный агент проверил код и исправил два воспроизведённых
регрессионными тестами случая: сохранение срока ровно в целевой момент и захват
двух уведомлений одной недели с разными ревизиями настройки.

До реализации: 17 ожидаемых ошибок, 31 тест прошёл. После исправлений:
целевой прогон — 46 тестов; полный `uv run pytest -q` — 387 тестов, 7.06 с.
`ruff check .` и `ruff format --check .` успешны; диагностика редактора без ошибок.
Живой запуск Telegram не выполнялся. Коммиты не создавались, задачи 8–9 не начаты.
