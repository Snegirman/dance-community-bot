> **Архив с 04.11.2026. Не использовать для дальнейшей реализации.**
> Владелец выбрал ввод по шаблону без нейросети и сохранил регулярные занятия
> с отменами и переносами. Актуальное описание:
> [согласованная спецификация](../specs/2026-11-04-structured-input-design.md)
> и [новый план реализации](2026-11-04-structured-input-mvp.md).

> отметки проверок относятся к прежнему этапу и не являются новой проверкой.

## Прежний план

**Цель:** владелец присылает материал, бот автоматически разбирает его и показывает
карточку для проверки; подтверждённые занятия и события публикуются по понедельникам
на соответствующую неделю вместе с оригинальными афишами.

**Архитектура:** один Python-процесс, Telegram через long polling, постоянная SQLite
и локальные файлы на постоянном диске. Распознавание OpenAI отделено от хранения
и публикации; недельный пост собирается из подтверждённых данных по шаблону.

**Стек:** Python 3.13, uv, aiogram 3, официальный OpenAI Python SDK, SQLite,
Ruff. Для реализации предложены Pydantic для схем и настроек, aiosqlite для
асинхронного доступа к SQLite и pytest для тестов. Зависимости добавляем только
в задаче, где появляется использующий их код, и фиксируем в `uv.lock`.

**Требования:** [README.md](../../../README.md), [AGENTS.md](../../../AGENTS.md)
и уточнение владельца от 04.11.2026: разбор начинается автоматически после получения
материала, без отдельной кнопки запуска. Перед допуском к публикации владелец
проверяет и подтверждает извлечённую информацию.

в группу. Время поста не подставляем автоматически.

## Особое внимание при проверке

1. Чужое сообщение, callback в группе или устаревшая кнопка не меняют данные — задачи 1 и 5.
2. Повторно доставленный материал, фотоальбом и позднее дополнение не создают
   несколько подтверждённых копий события — задачи 3 и 5.
3. Дата без года, противоречивые источники и неизвестная цена не превращаются
   в выдуманные факты — задача 4.
4. Событие на границе года и перенос занятия между неделями попадают в верный
   выпуск — задачи 6 и 7.
5. Потеря ответа Telegram после возможной отправки отличается от явного отказа;
   перезапуск не должен вслепую повторять сообщение — задачи 8, 9 и 11.

  расписания сохранять дату вступления в силу, чтобы не изменять прошлые недели.
  Разовое исключение не должно менять регулярное правило.
- [ ] Выполнить `uv run pytest tests/test_schedule.py -q`; внести реальное расписание
  только после получения дней, времени, места и стоимости от владельца.

**Готово, когда:** расписание задаётся один раз, а отмены и переносы относятся к конкретным датам.

### Задача 7. Недельный пост и предпросмотр

  попадают в пост; много тарифов, неизвестная цена и регистрационная ссылка сохраняются.
- [ ] Собрать шаблон разделов «Занятия» и «События», сортировку по дате и времени,
  сведения о месте/условиях и оригинальные афиши. Экранировать пользовательский текст.

- [ ] Реализовать `/preview` для текущей недели и выбора другой недели.

- [ ] Выполнить `uv run pytest tests/test_weekly.py -q`: при сборке поста вызовы

**Готово, когда:** владелец видит полный будущий выпуск с афишами, собранный только из базы.

### Задача 8. Ручная публикация и защита от повторов

**Зависимости:** 7.
**Файлы:** `publishing.py`, миграция журнала публикаций, `tests/test_publishing.py`.
**Контракт:** `async publish_week(post: WeeklyPost, group_id: int, store: Store,
bot: Bot) -> PublicationResult`; результат содержит статус и известные ID отправленных сообщений.

- [ ] Проверить повтор команды, одновременные запуски, отказ до отправки,
  частично отправленный выпуск и потерю ответа после возможной доставки.
  Успешно отправленные части не отправляются повторно.
- [ ] Сохранять снимок выпуска и журнал частей до сетевых вызовов; связывать
  публикацию с группой и неделей, а части — с устойчивым порядком и состояниями.
  Различать «подготовлена», «отправляется», «отправлена», «ошибка», «результат неизвестен».
  После перезапуска незавершённую отправку считать неоднозначной, пока не проверена.
- [ ] Реализовать `/publish` через предпросмотр и явное подтверждение отправки.
  Отправлять оригинальные изображения, сохранять возвращённые Telegram ID.
  При недоступном `file_id` использовать сохранённый оригинал. Уведомлять владельца
  о сбоях и показывать состояние частей выпуска.
- [ ] Для неизвестного результата остановить автоматический повтор; дать владельцу
  сверить чат и отметить часть как доставленную либо явно повторить. Не обещать
  абсолютное отсутствие дублей при неопределённом результате сетевого запроса.
  Выполнить `uv run pytest tests/test_publishing.py -q` и отправку в тестовую группу.

**Готово, когда:** выпуск можно отправить вручную, а повтор и частичный сбой обрабатываются осознанно.

- [ ] Реализовать согласованный снимок средствами SQLite и копирование связанных

**Готово, когда:** бот работает без открытого ноутбука, данные восстанавливаются,
а реальная первая понедельничная публикация проверена в целевой беседе.

## Критерии готовности первой версии

- [ ] Материал автоматически превращается в карточку для проверки.
- [ ] Подтверждённые записи сохраняются для своей недели, исправления и отмены работают.
- [ ] Регулярное расписание учитывает разовые отмены, переносы и замены.
- [ ] Пост содержит нужные сведения, тарифы и оригинальные афиши.
- [ ] Предпросмотр соответствует отправляемому выпуску; черновики в него не попадают.
- [ ] Посторонний пользователь не может управлять ботом.
- [ ] Понедельничный запуск работает без OpenAI и повторного подтверждения событий.
- [ ] Перезапуск, повтор команды и частичная отправка проверены; неизвестная доставка
  требует проверки, а не автоматического повтора.
- [ ] Очередь, уведомления, учёт расхода и восстановление резервной копии проверены.
- [ ] Доступы, модель, время, расписание и VPS заданы реальными значениями.

Текущее состояние реализации отмечено в задачах выше. Завершённые проверки
отмечаем отдельно от живой приёмки; описание будущего компонента не означает,
что он уже реализован.
