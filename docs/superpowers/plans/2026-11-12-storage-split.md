# Разделение хранилища на модули

> **For agentic workers:** использовать superpowers:subagent-driven-development;
> по AGENTS.md код переносит luna_worker, ревью и исправления выполняет главный агент.

**Goal:** заменить storage.py на пакет с модулями по областям ответственности,
сохранив поведение и импорт `from dance_community_bot.storage import Store`.

**Architecture:** отдельные классы частей хранилища наследуют общий базовый класс
соединений и преобразования общих данных. Store объединяет эти части; имена,
сигнатуры и асинхронные оболочки публичных методов сохраняются. Снимки каталога
выделены отдельно и доступны публикациям в том же SQLite-соединении.

**Tech Stack:** Python 3.13, SQLite, asyncio.to_thread, Pydantic, pytest, Ruff.

**Spec:** прямой запрос владельца от 12.11.2026: разбить storage.py на несколько
файлов. Поведение продукта, SQL, схема v5 и зависимости не меняются.

## Ограничения

- Сохранить текущие изменения, включая ещё не закоммиченные исправления.
- Каждый модуль хранилища должен быть меньше 1000 строк.
- Транзакция целиком остаётся внутри одного синхронного вызова в отдельном потоке.
- Никаких новых настроек, миграций, динамической подстановки методов или type ignores.
- Внешние импорты Store и используемые тестами приватные методы остаются рабочими.
- Не переходить к задаче 7 основного плана, не коммитить и не менять индекс Git.

## Файлы

- `src/dance_community_bot/storage/__init__.py`: публичный Store, объединяющий части.
- `storage/base.py`: путь, соединения, транзакции, инициализация, общие преобразования строк.
- `storage/sources.py`: исходные сообщения и вложения.
- `storage/records.py`: черновики, подтверждённые записи и отмены.
- `storage/snapshots.py`: согласованное чтение расписания и каталога, ревизия каталога.
- `storage/schedule.py`: предложения и применение изменений расписания, история исключений.
- `storage/publications.py`: выпуски, части, захваты отправки и восстановление.
- `storage/cards.py`: привязки сообщений и действия карточек.
- `README.md`: обновлённая карта файлов.

## Проверка рисков

- Перенос методов не меняет SQL, порядок запросов, commit/rollback или обработку ошибок.
- Получение schema.sql продолжает использовать корневой пакет dance_community_bot.
- Локальные импорты расписания и weekly разрешаются из нового подпакета без циклов.
- Store сохраняет все исходные методы, включая методы, используемые тестами гонок.
- Типизация общих методов явная; отсутствие ошибок редактора проверяется по новым файлам.
