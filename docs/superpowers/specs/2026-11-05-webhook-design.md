# Переход на webhook

05.11.2026 владелец выбрал webhook вместо постоянного опроса Telegram
и попросил реализовать переход. Локальная проверка предполагает HTTPS-туннель;
на общем сервере внешний HTTPS обслуживает reverse proxy.

## Подходы и границы

- Polling проще запускать локально, но создаёт запросы даже без новых сообщений.
- Webhook получает входящие POST от Telegram; нужен публичный HTTPS-адрес.
  Этот подход выбран владельцем. Поддержка двух режимов сейчас не требуется.
- Python 3.13, uv, aiogram 3 и действующие ограничения доступа сохраняются.
  Приём шаблонов, база и публикации остаются отдельными задачами.

## Технические решения

Следующие детали выбраны исполнителем в рамках перехода:

- Использовать aiohttp и интеграцию webhook из установленного aiogram.
- Слушать только `127.0.0.1`; локальный порт `WEBHOOK_PORT` по умолчанию 8080.
- Обязательны `TELEGRAM_WEBHOOK_URL` (полный HTTPS URL с путём обработчика)
  и `TELEGRAM_WEBHOOK_SECRET` (секрет заголовка Telegram).
- Проверять HTTPS, отсутствие credentials/query/fragment, корректность порта
  и допустимые символы и длину секрета. Ошибки не раскрывают введённые значения.
- Регистрировать webhook при запуске с секретом и используемыми типами updates.
  Не сбрасывать накопленные сообщения и не удалять webhook при остановке.
- Проверять секрет до передачи данных диспетчеру. Не подтверждать получение
  немедленно в фоне: использовать `handle_in_background=False`.
- Закрывать ресурсы при штатной остановке и при ошибках инициализации.
  Не логировать тело сообщений, токен, секрет или полный публичный URL.

## Проверка

Автономные тесты проверяют настройки, регистрацию без удаления updates,
отказ при отсутствующем/неверном секрете, передачу сообщения владельца,
сохранение барьера доступа и очистку ресурсов при сбоях.
Тесты не обращаются к Telegram. Живая проверка отдельно требует настоящих
настроек и доступного HTTPS-адреса; в эту работу она не входит.
